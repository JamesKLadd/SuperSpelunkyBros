# Super Spelunky Bros (working title)

A momentum platformer inside Spelunky 2: run-up speed, skids, a jump that
depends on how long you hold the button, a camera that only scrolls forward.
The hero keeps two Spelunky tools, the whip and two ropes.

Playlunky script mod for Spelunky 2 v2.5 (nightly Playlunky). Single-player.
All art is original and generated by a script in this repository.

**Status: milestone 1, the movement test room.** One test level, the hero's
movement, the camera and the level-strip system. No enemies, blocks, power-ups,
sound or HUD yet. Nothing here has been run in the game yet: see the checklist.

## Install

1. Put this folder in `Spelunky 2/Mods/Packs/` (any folder name works).
2. Build the generated files. This needs Python 3 with Pillow
   (`pip install pillow`):

   ```bash
   python tools/build_assets.py
   ```

   It writes `res/hero.png` and `Data/Levels/ssb_blank_8x*.lvl` into the pack.
   Without this step the level cannot load. Run it again after every update
   of the mod: the generated files change with it.
3. Enable the pack in Playlunky and accept the unsafe-mode warning (the mod
   reads a flag file and writes a trace file, nothing else).
4. Start a run from the camp. The first level is the test room.

Disable the pack to get the normal game back.

## Options

By default the hero is drawn from the game's **red character sheet**
(`char_red.png`), whichever character you pick. To choose the hero's look, put
your own character sheet at `Data/Textures/char_red.png` in a Playlunky pack
(this one or any other); it must use the vanilla character sheet layout. That
file is yours and stays on your machine: `Data/` is ignored by git.

In Playlunky's script options for this mod:

- **Keep my selected character**: play as the character you picked on the
  character select screen instead. Off by default.
- **Use the mod's built-in hero**: use the sheet `tools/build_assets.py`
  generates (`res/hero.png`). Off by default. Only this sheet has a skid pose.

Both take effect at the next level. Movement is the same in every case.

## Controls

Spelunky's own bindings: move, jump, run, whip, rope, crouch. The bomb button
does nothing for now (it is reserved for the projectile power-up).

## Debug trace

Create an empty file named `ssb_trace.on` in the pack folder, next to
`main.lua`. From the next level start:

- `ssb_trace.log` is written in the pack folder: a header, one CSV row per
  frame, and `# event` lines (jumps, the strip seam, restarts, ignored damage).
  It is overwritten at every level start, so copy it before restarting.
- A line of live numbers is drawn at the top left: speed in 8-bit pixels per
  frame next to the walk and run targets, vertical speed, ground or air, jump
  tier, position, strip.

Delete the file to turn both off. No restart needed either way.

When something looks wrong, send `ssb_trace.log` and the checklist item.

### If the game crashes

If it crashes right at level start after an update that touched the hero, try
once with an empty file named `ssb_vanilla_ledge.on` in the pack folder: it
turns off the one part that rewires the player's state machine. Tell me either
way.

`ssb_boot.log` in the pack folder is always written, no flag needed: one line
per step of loading the script and of loading a level, flushed as each step
starts. After a crash, the last line is the step that did not finish. Send that
file (it is overwritten the next time the game starts).

## Test checklist: milestone 1

The test room, left to right: a runway, ledges 2 to 6 tiles up, a low ceiling,
trenches 2, 3, 4 and 6 wide, a staircase, a real pit, a 3-tile wall.

Turn the trace on first. For each item, "ok" or what you saw instead.

**Loading**

1. The level is a flat floor with floating ledges, not a Dwelling level. The
   tiles and background still look like the Dwelling for now.
   If you get a normal Dwelling level, tell me, and whether any `[SSB ERROR]`
   line showed on screen.
2. The hero is drawn from the red character sheet from the first level on,
   whichever character you picked. The view is zoomed out (about 25 tiles wide).
3. The HUD shows 0 bombs and 2 ropes.

**Ground movement**

4. Hold right: speed builds over about 0.7 s instead of starting instantly.
   The overlay's `vx` settles on 1.56.
5. Hold run + right: `vx` settles on 2.56.
6. At full run, hold left: the hero slides a tile or two in a skid pose before
   turning (overlay shows `SKID`).
7. At full run, let go: coasts to a stop over three to five tiles.
8. Legs animate while moving, faster at a run. No sliding in a standing pose.

**Jumping**

9. Tap jump: a hop of about one tile.
10. Hold jump from a standstill: lands on the ledge 4 up (third one), cannot
    reach the ledge 5 up.
11. Running jump: lands on the ledge 5 up. Nothing reaches the ledge 6 up.
12. Jump under the low ceiling: head bonks and the hero drops, no sticking.
13. Running jumps clear the 2, 3 and 4 wide trenches; the 6 wide one needs a
    full run-up.
14. In the air with no direction held, the hero keeps its speed.

**Things that must not happen**

15. Jump at the 3-tile wall and hold toward it, and jump at the ledge 5 up
    from a standstill: no ledge-grab, no wall-cling, no hanging pose.
16. The bomb button does nothing.
17. Long falls (off the staircase): no stun, no damage.

**Things that must still work**

18. Whip, on the ground and in the air.
19. Throw a rope, climb it, jump off it sideways.

**Camera**

20. The camera follows to the right, with the hero a little left of centre.
21. Walk back left: the camera stays, and the hero stops at the screen's left
    edge.
22. The camera never moves up or down.

**The strip seam** (around the first trench, a third of the way in)

23. Walk right through it. The layout should not jump. The dirt texture and
    the cave background behind it may change in that one frame; that is
    expected for now. Anything else (a flash, a camera pan, the hero
    displaced, a hitch) is a bug: tell me what you saw.
24. After the seam, everything still works as before.

**Restart**

25. Fall into the real pit (past the staircase): the level restarts from the
    beginning.

**Leaving**

26. Quit to the camp: zoom is back to normal.

## Repository layout

```
main.lua              loads the modules below, in order
src/util.lua          dbg / SafeCall / pack paths
src/trace.lua         flag-file trace log
src/physics.lua       the movement model (pure Lua, unit-tested)
src/levelgrid.lua     level grids and strip maths (pure Lua, unit-tested)
src/levels/           level definitions
src/level.lua         loads a blank level, places tiles, seam, kill plane
src/camera.lua        forward-only camera
src/hero.lua          connects the model to the player entity
src/assets.lua        custom textures
src/game.lua          callback registration and per-frame order
src/vendor/           third-party code (CustomLevels, Apache-2.0)
tools/build_assets.py generates res/ and Data/
tools/update_api_manifest.py  refreshes tests/api_manifest.json
tests/                pytest suite, with a stub engine
docs/COMPROMISES.md   where the design bends to fit the engine
```

## Tests

```bash
pip install pytest lupa pillow
```

```bash
python -m pytest tests -q
```

The suite compiles every Lua file under Lua 5.4, checks every engine function,
enum member and field the mod uses against the real API
(`tests/api_manifest.json`, generated from Overlunky's definitions), pins the
physics numbers, and runs `main.lua` against a stub engine. The stub is not
Spelunky 2: it proves the Lua runs and keeps its own rules, not that the real
engine responds the way the stub does. The checklist above is for that.

## For later: online play

Nothing here does networking, but it is written not to get in the way of
Modded-Online: gameplay runs only in update callbacks and entity hooks, on
frame counts; the hero acts on whatever is in `buttons_gameplay` when the
update starts, so an input-sync layer that rewrites it is obeyed; nothing uses
wall-clock time or unseeded randomness.
